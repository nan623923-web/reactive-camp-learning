# 第一次部署：先在自己电脑上编译

这份练习只做一件事：把官方 Xfers 放进 Foundry，在本地编译并通过离线测试。

它监听 Ethereum Sepolia 上所有 ERC-20 的 `Transfer`，在 Lasna 上把金额按代币地址累加。次数用完后，合约自己退订。没有目标链回调，也不会在 Base Sepolia 上写表。用例拆解卡仍然是以后的想法，这次不要一起做。

你还没有部署。这次也不部署。

## 两个区别

**本地代码**是 `src/Xfers.sol` 这个文件，躺在 Ubuntu 硬盘上。改它、编译它，Lasna 上都没有新合约。

**已经部署的合约**是 Lasna 上的一个地址。只有一笔被签名并接受的部署交易，才会产生这个地址。部署之后，链上的代码不会跟着你本地文件自动变。

**编译**是 `forge build`。它在本地把 Solidity 变成字节码，保存在 `out/`。不需要钱包，不花 lREACT。

**广播**是命令里带 `--broadcast` 的那一步。Foundry 会用钥匙签名，把交易发到 Lasna。那会花测试币，并可能真的部署合约。那些命令在最后，现在不要运行。

## 现在只做第 1 步

在 Windows 里打开 Ubuntu 终端，不是 PowerShell。把收到的 `first-deploy-practice.zip` 放进 `~/reactive-camp-work/`。不要 git clone 官方仓库，也不要 git clone 学习仓库。

然后整段复制这一次：

```bash
cd ~/reactive-camp-work
unzip -o first-deploy-practice.zip
cd first-deploy-practice
forge build
```

第一次编译可能下载 solc `0.8.29`。那是编译器，不是交易。

成功时，末尾附近有：

```text
Compiler run successful!
```

看到这句话就停。把这段输出留给自己。不要接着部署。

`unzip` 如果说找不到 zip，也停下来。先确认压缩包在 `~/reactive-camp-work/first-deploy-practice.zip`。

## 第 2 步：本地测试（编译成功后再做）

```bash
cd ~/reactive-camp-work/first-deploy-practice
forge test -vv
```

成功时能看到每条测试是 PASS。这里的系统合约是测试里的替身：Foundry 把替身的代码放到 `0x8888888888888888888888888888888888888888`，再用 `vm.prank` 假装调用者是它。

这证明的是本地逻辑：

- 构造时订阅 Sepolia（链 id `11155111`）、任意合约地址、`Transfer` 的 topic0
- 部署时附带的 `0.1 ether` 留在合约余额里，没有在构造时转给系统合约
- 别人不能调用 `react()`，只有系统地址可以
- 两次 `opCode == 3` 的日志会累加金额，次数到 0 时退订
- `opCode` 不是 3 时不计
- 官方 `react()` 自己不再检查 topic0；筛选靠订阅条件
- 次数已经是 0 时再调用一次会算术下溢。这是官方代码的行为，练习没有改它
- 只有部署者能 `updateLimit`
- 限额改成非 0 时，会按系统合约返回的欠款，把相应余额打给系统地址
- 直接往合约转币，币留在合约里

这不能证明 Lasna 已经订阅成功，也不能代替一笔真实的 react 交易链接。

## 费用从哪扣

一次 `react()` 的费用仍然是：

```text
费用 = 较高的 gas 价格 × 系数 ×（实际消耗 gas + 固定附加 gas）
```

系数是 `_gasPriceCoeffPer1000 / 1000`。2026-11-22 读到的是 1。固定附加 gas 是 `100000`。`react()` 失败也会收费，因为计算已经发生。`_maxChargeGas` 不进这个公式，它限制系统调用 `pay()` 时最多能用多少 gas。

三个数要分开：

| 名字 | 在哪里 | 含义 |
| --- | --- | --- |
| balance | 反应合约自己的地址 | 合约口袋里的 lREACT |
| reserves | 系统合约替这个地址记的账 | 预付额度，只用来付费 |
| debt | 系统合约替这个地址记的账 | 还没付清的费用 |

官方当前系统合约 `AbstractProxiedPayableBridge._charge` 的顺序是：

1. `trigger()` 一开始如果 `debt > 0`，直接拒绝，不会调用 `react()`。
2. `debt` 为 0 才执行 `react()`。就算 `react()` 回滚，后面仍然计费。
3. 有 reserves 时先扣 reserves。够付就结束，不调用 `pay()`。
4. reserves 不够或本来就是 0：先把这笔费用加进 debt，然后调用反应合约的 `pay(全部欠款)`。这次调用的 gas 不超过 `_maxChargeGas`。
5. 官方 `AbstractPayer.pay()` 只接受系统合约调用。余额够，就把这笔 lREACT 转回系统合约。系统合约的 `receive()` 走 `_deposit`：先还 debt，剩下的才变成 reserves。同一次交易里 debt 回到 0，就不会拉黑。
6. 余额不够时，`pay()` 回滚，错误是 `InsufficientFunds(uint256,uint256)`，选择器 `0x03eb8b54`。系统发出 `PaymentFailure`。debt 还大于 0，于是发出 `BlacklistContract`。之后不再调用 `react()`，也就不会再自动调用 `pay()`。

所以：

- 预付的 reserves 会先被使用。
- reserves 用尽时，自动 `pay()` 可以从合约余额里结算。不能再说「只有预充值，完全不会自动扣」。
- 直接把币转到合约地址，当时只增加 balance。它不会当场增加 reserves，也不会当场清掉已经存在的 debt。
- 合约仍然是 debt 为 0 时，下次计费可以自动 `pay()`，把 balance 付出去。
- 合约已经有 debt 时，光转账不够。任何人都可以对系统合约调用 `depositTo(反应合约地址)`，先还债，剩下的记入 reserves。部署者也可以调用 `updateLimit(非 0)`：官方 Xfers 会在里面先执行内部的 `_coverDebt()`，从 balance 还债。Xfers 没有单独公开的 `coverDebt()`。

官方 `XFERS.md` 的部署命令带 `--value 0.1ether`。Xfers 的构造函数是 `payable`，所以这笔钱进入合约 balance，不是 `depositTo` 的 reserves。后面的自动 `pay()` 会在 reserves 为 0 时使用这笔余额。

官方说明里的那条 `cast run` 轨迹是失败例子：`pay()` 回滚，随后是 `PaymentFailure` 和 `BlacklistContract`。交易本身被系统合约执行完，不代表反应合约付清了费用。

## 第 4 步：钥匙放进本机钥匙库（现在不要做）

以后签名只用 Foundry 钥匙库和 `--account`。不要使用 `--private-key`，不要把私钥写进命令，不要写进 `.env`，不要贴到聊天里。官方 `XFERS.md` 的示例带有 `--private-key`。那些命令不要照抄。

等你决定要部署、并且已经在聊天里说可以之后，在 Ubuntu 终端自己运行。提示出现时再输入。输入过程不显示字符：

```bash
cast wallet import lasna --interactive
```

它会要一个钥匙库密码，然后要私钥。密码和私钥都只留在这台电脑的提示里。密码也不要发到聊天。

不要使用帮助文本里的 `--private-key`、`--mnemonic`、`--unsafe-password`。

导入结束后先看钥匙库里有没有这个名字。这条命令不签名，也不要密码：

```bash
cast wallet list
```

列表里应有 `lasna`。要打印地址时再运行：

```bash
cast wallet address --account lasna
```

终端会在本机索要钥匙库密码。这只是从钥匙库算出地址，不发送交易。密码不要发到聊天。打印出的地址应当是 `0xfc118609d291391df2eA4975d39866256d47f5AA`。不是这个地址就停，不要部署。

## 第 5 步：部署（现在不要做）

必须同时满足：第 1 步到第 3 步你自己跑过；钥匙已经在本机钥匙库；你在聊天里明确同意由你自己发送这笔交易。

在 `first-deploy-practice` 目录里，由你自己执行：

```bash
cd ~/reactive-camp-work/first-deploy-practice
forge create \
  --rpc-url https://lasna-rpc.rnk.dev/ \
  --chain 5318007 \
  --account lasna \
  --broadcast \
  --value 0.1ether \
  src/Xfers.sol:Xfers \
  --constructor-args 2
```

Foundry 会在本机提示输入钥匙库密码。

这里的 `2` 是官方构造参数「自动退订前最多处理多少次」。官方页面示例写的是 `10`。订阅范围是 Sepolia 上每一个 ERC-20 `Transfer`，不是某一个代币。次数会很快被用完，每一次 react 都要付费。第一次用 `2`，少花一点测试币。合约代码没有改。

`--value 0.1ether` 是官方示例的金额，进入新合约的 balance。部署交易的 gas 另外从钱包扣。第 3 步看到的余额如果不够 `0.1` lREACT 再加 gas，就停，不要把金额改大。

命令成功后，终端会打印 `Deployed to:` 后面的地址。把这个地址记下来。那才是链上合约。本地的 `src/Xfers.sol` 仍然只是源码。

这一步完成之前，不存在 react 交易链接。部署交易本身也不是 react 交易。

## 第 6 步：等 react，并核对（部署成功之后再做）

这些读取不签名。把 `合约地址` 换成上一笔的地址：

```bash
cast call --rpc-url https://lasna-rpc.rnk.dev/ 合约地址 "_limit()"
cast call --rpc-url https://lasna-rpc.rnk.dev/ 合约地址 "_lastReactBlockNumber()" | cast to-dec
cast call --rpc-url https://lasna-rpc.rnk.dev/ 合约地址 "_lastTxHash()"
cast call --rpc-url https://lasna-rpc.rnk.dev/ 0x8888888888888888888888888888888888888888 "debt(address)(uint256)" 合约地址
cast balance 合约地址 --rpc-url https://lasna-rpc.rnk.dev/ --ether
cast call --rpc-url https://lasna-rpc.rnk.dev/ 0x8888888888888888888888888888888888888888 "reserves(address)(uint256)" 合约地址
```

`_lastReactBlockNumber()` 变成非 0 后，到 <https://lasna.reactscan.net/> 打开那个区块，找到调用你的合约的 react 交易。作业要的是这个 Lasna 交易链接，外加已部署的合约地址。

`_limit()` 会变小。到 0 后，合约已经退订。Sepolia 上还要有人发出 `Transfer`，Lasna 才会出现 react。没有人转账时，计数可以一直不变。这不等于编译失败。

如果 `debt` 大于 0，系统已经停止调用。恢复时优先用 `depositTo`，因为它不依赖合约是否公开了 `coverDebt()`。下面这句会签名、会花钱，现在不要运行。将来也要先在聊天里确认，再由你自己执行：

```bash
cast send \
  --rpc-url https://lasna-rpc.rnk.dev/ \
  --chain 5318007 \
  --account lasna \
  0x8888888888888888888888888888888888888888 \
  "depositTo(address)" 合约地址 \
  --value 0.05ether
```

官方 `cast call` 示例写了 `--private-key`。读取不需要私钥。上面的 `cast call` 没有钥匙参数。
