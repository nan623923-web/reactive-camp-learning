# 回调练习：这次只编译

上一次的 Xfers 只在 Lasna 上听 Sepolia 转账并计数。这次多出来的是第三步：Lasna 上的 `react()` 可以请 Sepolia 上的另一个合约执行 `onEvent`。源链和目标链按官方模板都用 Ethereum Sepolia，中间仍然经过 Lasna。这是三笔交易，不是一笔。

三个合约：

1. `CampOrigin` 在 Sepolia 上发出 `Ping`。
2. `CampReactive` 在 Lasna 上收这个事件。数值达到 100 才请求回调。
3. `CampCallback` 在 Sepolia 上接受回调。直接调用它会被拒绝，只有 Callback Proxy 才能进来。

第一次部署的合约 `0x298c78B4d1F0ecAb2b4cD2D477a1abCD4C2d32e6` 保持不动。这个新目录和 `first-deploy-practice` 并列，不要混在一起。

## 现在只做这一步

Ubuntu 终端。把 `callback-practice.zip` 放进 `~/reactive-camp-work/`。不要 git clone。

```bash
cd ~/reactive-camp-work
unzip -o callback-practice.zip
cd callback-practice
forge build
```

成功时看到 `Compiler run successful!` 就停。后面如果还有两行 `warning`，那是官方合约的检查提示，这次不改合约。这一步不签名，不花钱。

## 编译成功后再做（仍然不上链）

```bash
cd ~/reactive-camp-work/callback-practice
forge test -vv
```

官方模板是 8 个测试。其中 `test_callbackRejectsWrongProxy` 就是「别人直接调用回调，调用失败，计数不变」。`test_callbackRejectsWrongSender` 是代理投递了错误的来源地址，同样失败。这两条就是拒绝实验，发生在本地，不花 gas。

作业目前要的链上材料是三笔成功交易的链接。官方 README 没有要求再发一笔必定失败的链上交易。失败截图先用上面这两条测试的输出。除非之后在聊天里确认必须是浏览器上的失败交易，否则不要为了截图去发一笔会回滚的交易。
